# Проблема с обработкой движения на бэкенде

## Описание проблемы

Сервер **игнорирует движение от клиента** и **телепортирует игрока обратно в центр** или двигает его в неправильном направлении.

## Доказательства из логов

### Пример 1: Сервер телепортирует игрока в центр

```
[Server Position Update] Большая разница между сервером и клиентом!
{
  serverPos: {x: '0.00', y: '0.00'},        // ❌ Сервер говорит, что игрок в центре
  localPos: {x: '-8.52', y: '-0.90'},       // ✅ Клиент думает, что игрок здесь
  distance: '8.57',                         // Разница 8.57 единиц!
  serverDistanceFromCenter: '0.00',
  serverMaxAllowed: '735.00',
  safeZoneRadius: '740.00',
  mapRadius: '803.00',
  note: 'Сервер отклонил движение или скорректировал позицию'
}
```

**Проблема:** Клиент отправляет движение (`Movement SENT`), но сервер возвращает позицию `(0, 0)` вместо обновленной позиции.

### Пример 2: Сервер двигает игрока только вправо

```
[Server Position Update] Большая разница между сервером и клиентом!
{
  serverPos: {x: '9.22', y: '0.00'},        // ❌ Сервер двигает только по X
  localPos: {x: '-3.83', y: '-1.02'},       // ✅ Клиент двигается в другую сторону
  distance: '13.09'
}

serverPos: {x: '31.65', y: '0.00'}         // ❌ Продолжает двигать только вправо
serverPos: {x: '56.13', y: '0.00'}         // ❌ Игнорирует движение клиента
serverPos: {x: '80.92', y: '0.00'}         // ❌ Y всегда 0!
```

**Проблема:** Сервер игнорирует `dy` от клиента и двигает игрока только по оси X.

### Пример 3: Клиент отправляет движение, но сервер его игнорирует

```
[Movement Debug] Movement SENT 
{
  dx: '-0.2178',                            // ✅ Клиент отправляет движение влево
  dy: '-0.0230',                            // ✅ И немного вверх
  magnitude: '0.2190',
  timeSinceLastMove: '22.20ms'
}

// Но сервер возвращает:
serverPos: {x: '0.00', y: '0.00'}          // ❌ Игнорирует движение!
```

## Что происходит на клиенте

1. ✅ Клиент **правильно вычисляет** движение на основе мыши/клавиатуры
2. ✅ Клиент **правильно ограничивает** движение границами `safe_zone`
3. ✅ Клиент **отправляет движение** на сервер через `socket.emit("move", { dx, dy })`
4. ❌ Сервер **игнорирует** движение и возвращает неправильную позицию

## Что нужно исправить на бэкенде

### 1. Обработка события `move`

**Текущее поведение (неправильно):**
```python
# ❌ НЕПРАВИЛЬНО - игнорирует движение
def handle_move(socket, data):
    player = get_player(socket.user_id)
    # Движение игнорируется или обрабатывается неправильно
    player.x = 0  # ❌ Телепортирует в центр
    player.y = 0
```

**Правильное поведение:**
```python
# ✅ ПРАВИЛЬНО - обрабатывает движение
def handle_move(socket, data):
    player = get_player(socket.user_id)
    dx = data.get('dx', 0)  # Получаем движение по X
    dy = data.get('dy', 0)  # Получаем движение по Y
    
    # Вычисляем новую позицию
    new_x = player.x + dx
    new_y = player.y + dy
    
    # Проверяем границы safe_zone
    safe_zone = get_safe_zone()
    distance_from_center = math.sqrt(new_x**2 + new_y**2)
    max_distance = safe_zone.radius - player.mass
    
    if distance_from_center > max_distance:
        # Ограничиваем позицию, НЕ телепортируем в центр!
        angle = math.atan2(new_y, new_x)
        player.x = math.cos(angle) * max_distance
        player.y = math.sin(angle) * max_distance
    else:
        # Обновляем позицию
        player.x = new_x
        player.y = new_y
```

### 2. Отправка `game_state`

**Проблема:** Сервер отправляет `game_state` с позицией `(0, 0)` вместо реальной позиции игрока.

**Решение:** Отправлять актуальную позицию после обработки движения:
```python
# ✅ ПРАВИЛЬНО
game_state = {
    "players": [
        {
            "player_id": player.id,
            "x": player.x,  # ✅ Реальная позиция после обработки движения
            "y": player.y,  # ✅ Не (0, 0)!
            "mass": player.mass
        }
    ],
    "safe_zone": {
        "x": safe_zone.x,
        "y": safe_zone.y,
        "radius": safe_zone.radius
    }
}
```

### 3. Обработка обоих направлений (X и Y)

**Проблема:** Сервер обрабатывает только `dx`, игнорируя `dy`.

**Решение:** Обрабатывать оба направления:
```python
# ✅ ПРАВИЛЬНО - обрабатываем оба направления
new_x = player.x + dx  # ✅ Обрабатываем X
new_y = player.y + dy  # ✅ Обрабатываем Y (не игнорируем!)
```

## Проверка исправления

После исправления в логах должно быть:

```
[Server Position Update] - НЕ должно появляться
// или если появляется, то distance должна быть < 1.0

[Movement Debug] Movement SENT 
{
  dx: '-0.2178',
  dy: '-0.0230'
}
// Сервер должен вернуть позицию, которая учитывает это движение
serverPos: {x: 'player.x - 0.2178', y: 'player.y - 0.0230'}  // ✅
```

## Важные моменты

1. **НЕ сбрасывать позицию в центр** при обработке движения
2. **Обрабатывать оба направления** (dx и dy)
3. **Ограничивать движение границами safe_zone**, а не телепортировать
4. **Отправлять актуальную позицию** в `game_state`, а не `(0, 0)`
