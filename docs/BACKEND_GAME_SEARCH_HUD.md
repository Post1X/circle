# Документация для бекенда: Поиск игры HUD

## Обзор

Данная документация описывает WebSocket API для функциональности поиска игры (Game Search) и отображения HUD (Head-Up Display) во время поиска. Система позволяет игрокам искать доступные игровые комнаты, создавать новые комнаты и присоединяться к существующим.

## WebSocket подключение

- **URL**: `/ws`
- **Протокол**: Socket.IO
- **Транспорт**: WebSocket

## Аутентификация

Перед использованием API поиска игры клиент должен пройти аутентификацию:

### Событие: `authenticate`

**Клиент → Сервер:**
```json
{
  "user_id": "string (UUID)"
}
```

### Событие: `authenticated`

**Сервер → Клиент:**
```json
{
  "user_id": "string (UUID)",
  "username": "string"
}
```

### Событие: `auth_error`

**Сервер → Клиент:**
```json
{
  "message": "string"
}
```

## API поиска игры

### 1. Получение списка комнат

#### Событие: `get_rooms`

**Клиент → Сервер:**
```json
// Пустое тело запроса
```

**Описание:** Запрос на получение списка доступных игровых комнат.

#### Событие: `rooms_list`

**Сервер → Клиент:**
```json
{
  "rooms": [
    {
      "room_id": "string",
      "entry_fee": 0,
      "min_players": 2,
      "max_players": 50,
      "status": "string",
      "created_at": "string (ISO 8601)"
    }
  ]
}
```

**Структура Room:**
- `room_id` (string) - Уникальный идентификатор комнаты
- `entry_fee` (number) - Вступительный взнос (в текущей реализации: 0)
- `min_players` (number) - Минимальное количество игроков для старта
- `max_players` (number) - Максимальное количество игроков в комнате
- `status` (string) - Статус комнаты (например, "waiting", "starting", "in_progress")
- `created_at` (string) - Время создания комнаты в формате ISO 8601

**Логика фильтрации на клиенте:**
- Клиент фильтрует комнаты, созданные не более 30 секунд назад (0.5 минуты)
- Используется самая старая комната для присоединения

### 2. Создание новой комнаты

#### Событие: `create_room`

**Клиент → Сервер:**
```json
{
  "entry_fee": 0,
  "min_players": 2,
  "max_players": 50
}
```

**Параметры:**
- `entry_fee` (number) - Вступительный взнос (обычно 0)
- `min_players` (number) - Минимальное количество игроков (обычно 2)
- `max_players` (number) - Максимальное количество игроков (обычно 50)

**Описание:** Создание новой игровой комнаты. Клиент создает комнату автоматически, если нет доступных комнат.

#### Событие: `room_created`

**Сервер → Клиент:**
```json
{
  "room_id": "string",
  "entry_fee": 0,
  "min_players": 2,
  "max_players": 50,
  "status": "string",
  "created_at": "string (ISO 8601)"
}
```

**Описание:** Подтверждение создания комнаты. После получения этого события клиент запрашивает обновленный список комнат.

### 3. Присоединение к комнате

#### Событие: `join_room`

**Клиент → Сервер:**
```json
{
  "room_id": "string"
}
```

**Параметры:**
- `room_id` (string) - Идентификатор комнаты для присоединения

**Описание:** Запрос на присоединение к игровой комнате.

#### Событие: `joined_room`

**Сервер → Клиент:**
```json
{
  "room_id": "string",
  "players": [
    {
      "username": "string",
      "user_id": "string (UUID)"
    }
  ],
  "message": "string",
  "time_to_start": number | null
}
```

**Параметры:**
- `room_id` (string) - Идентификатор комнаты
- `players` (array) - Список игроков в комнате
  - `username` (string) - Имя пользователя
  - `user_id` (string) - UUID пользователя
- `message` (string) - Сообщение от сервера
- `time_to_start` (number | null) - Время до старта игры в секундах (null, если игра не готова к старту)

**Описание:** Подтверждение успешного присоединения к комнате. После этого клиент переходит в лобби.

### 4. Обработка ошибок

#### Событие: `error`

**Сервер → Клиент:**
```json
{
  "message": "string"
}
```

**Описание:** Общая ошибка, связанная с операциями поиска игры.

## Логика работы поиска игры

### Последовательность действий клиента:

1. **Подключение и аутентификация:**
   - Клиент подключается к WebSocket (`/ws`)
   - Отправляет `authenticate` с `user_id`
   - Ожидает `authenticated` или `auth_error`

2. **Запрос списка комнат:**
   - После успешной аутентификации отправляет `get_rooms`
   - Получает `rooms_list` с массивом доступных комнат

3. **Фильтрация комнат:**
   - Клиент фильтрует комнаты, созданные не более 30 секунд назад
   - Если есть доступные комнаты, выбирается самая старая

4. **Создание комнаты (если нужно):**
   - Если нет доступных комнат, клиент автоматически создает новую через `create_room`
   - После `room_created` запрашивает обновленный список через `get_rooms`

5. **Определение готовности игры:**
   - Игра считается готовой, если:
     - Прошло не менее 15 секунд с начала поиска
     - Есть доступные комнаты (после фильтрации)

6. **Присоединение к комнате:**
   - При нажатии "Accept" клиент присоединяется к самой старой доступной комнате
   - Отправляет `join_room` с `room_id`
   - Получает `joined_room` и переходит в лобби

### Таймер поиска:

- Клиент отслеживает время поиска локально
- Формат отображения: `MM:SS`
- Игра становится доступной после 15 секунд поиска при наличии комнат

## HUD во время поиска

### Отображаемая информация:

1. **Заголовок:** "GAME SEARCH"
2. **Регион:** "Region 1" (статическое значение)
3. **Ставка:** "10 SOL" (статическое значение)
4. **Время поиска:** Таймер в формате `MM:SS`
5. **Кнопка отмены:** Возможность отменить поиск

### Состояние "Игра готова":

Когда игра становится доступной (≥15 секунд и есть комнаты):

1. **Заголовок:** "YOUR GAME IS READY"
2. **Кнопка "Accept":** Присоединяется к самой старой доступной комнате
3. **Кнопка "Decline match":** Отменяет поиск и возвращает на главную

## Требования к бекенду

### Обязательные функции:

1. **Управление комнатами:**
   - Хранение списка активных комнат
   - Автоматическое удаление старых комнат (старше 30 секунд)
   - Отслеживание статуса комнат

2. **Валидация:**
   - Проверка аутентификации перед операциями с комнатами
   - Проверка существования комнаты при присоединении
   - Проверка лимита игроков в комнате

3. **Синхронизация:**
   - Уведомление всех клиентов об изменениях в списке комнат
   - Обновление списка игроков в комнате при присоединении/выходе

4. **Обработка ошибок:**
   - Возврат понятных сообщений об ошибках
   - Обработка случаев, когда комната заполнена или не существует

### Рекомендации:

1. **Оптимизация:**
   - Кэширование списка комнат для быстрого доступа
   - Периодическая очистка неактивных комнат

2. **Масштабируемость:**
   - Использование Redis или аналогичного решения для хранения комнат
   - Поддержка нескольких регионов

3. **Безопасность:**
   - Проверка прав доступа к комнатам
   - Защита от спама создания комнат
   - Rate limiting для операций создания/присоединения

## Примеры использования

### Пример 1: Успешный поиск игры

```
1. Клиент → Сервер: authenticate({ user_id: "123e4567-e89b-12d3-a456-426614174000" })
2. Сервер → Клиент: authenticated({ user_id: "...", username: "player1" })
3. Клиент → Сервер: get_rooms()
4. Сервер → Клиент: rooms_list({ rooms: [] })
5. Клиент → Сервер: create_room({ entry_fee: 0, min_players: 2, max_players: 50 })
6. Сервер → Клиент: room_created({ room_id: "room-123", ... })
7. Клиент → Сервер: get_rooms()
8. Сервер → Клиент: rooms_list({ rooms: [{ room_id: "room-123", ... }] })
9. [Через 15+ секунд] Клиент → Сервер: join_room({ room_id: "room-123" })
10. Сервер → Клиент: joined_room({ room_id: "room-123", players: [...], time_to_start: 10 })
```

### Пример 2: Присоединение к существующей комнате

```
1. Клиент → Сервер: authenticate({ user_id: "..." })
2. Сервер → Клиент: authenticated({ ... })
3. Клиент → Сервер: get_rooms()
4. Сервер → Клиент: rooms_list({ 
     rooms: [
       { room_id: "room-123", created_at: "2024-01-01T12:00:00", ... },
       { room_id: "room-124", created_at: "2024-01-01T12:00:10", ... }
     ]
   })
5. [Клиент выбирает room-123 как самую старую]
6. [Через 15+ секунд] Клиент → Сервер: join_room({ room_id: "room-123" })
7. Сервер → Клиент: joined_room({ room_id: "room-123", players: [...], ... })
```

### Пример 3: Ошибка при присоединении

```
1. Клиент → Сервер: join_room({ room_id: "invalid-room" })
2. Сервер → Клиент: error({ message: "Room not found" })
```

## Примечания

- Все временные метки должны быть в формате ISO 8601
- UUID должны быть в стандартном формате (например, `123e4567-e89b-12d3-a456-426614174000`)
- Клиент автоматически создает комнату, если список пуст
- Фильтрация комнат по времени (30 секунд) выполняется на клиенте, но рекомендуется также на бекенде
- Статус комнаты может быть: `waiting`, `starting`, `in_progress`, `finished`
